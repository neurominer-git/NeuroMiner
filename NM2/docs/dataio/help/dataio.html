Training modalities

Three NM2 words used below: A case is one observation that NM2 analyses—for example one person, participant, scan or sample. A modality is one block of measurements collected for a set of cases, for example questionnaire scores, MRI voxels, ROI values or connectivity edges. A feature is one input measurement that the machine-learning model uses.

A training dataset contains one or more modalities. For example, modality 1 contains clinical questionnaire variables and modality 2 contains MRI features from the same or overlapping cases.

  1. Click Add modality to import a new block of training data.
  2. Use Modify selected to reopen a modality that has already been committed.
  3. Use Resume selected to continue an unfinished import task.
  4. Check the modality overview and diagnostics until every required training modality is ready.
  5. Click Finalize training data import only when the training dataset is complete.
Important: finalizing training import is a checkpoint. Confirm that the required modalities, cases, features and labels are correct before you pass it.
Advanced details

The modality manager displays backend DataIO state and capability information. Finalization changes the workflow stage and therefore the actions that NM2 permits next.

OOCV / application data manager

Three NM2 words used below: A case is one observation that NM2 analyses—for example one person, participant, scan or sample. A modality is one block of measurements collected for a set of cases, for example questionnaire scores, MRI voxels, ROI values or connectivity edges. A feature is one input measurement that the machine-learning model uses.

OOCV means independent application data: cases that were not used to train the model. Examples are an external validation cohort or new cases to which a trained model will be applied.

  1. Enter a clear name or description for the OOCV dataset.
  2. Tick Labels available for evaluation when the true outcomes/classes are available.
  3. Click Create OOCV dataset.
  4. Select the new OOCV dataset.
  5. Import the modality or modalities required by the trained analysis.
  6. When one OOCV container contains cases from several study groups, click Configure study groups... after the first modality has established the container Case-ID axis. Read one numeric group-label vector from the MATLAB workspace or a CSV/spreadsheet and align it by Case ID or explicit row order. You can give the groups descriptive names and select one reference group.

The OOCV dataset does not need the same number of cases or the same class proportions as the training dataset. Study-group labels stratify downstream OOCV evaluation; they do not create separate OOCV containers or alter the modality data.

Advanced details

DataIO allows an OOCV dataset to be built one modality at a time. Study groups belong to the OOCV container Case-ID axis and therefore apply to all modalities in that container. DataIO converts the distinct numeric source labels to the backend group IDs 1..K and stores the source mapping, names and optional reference group. The selected trained analysis determines which modalities must be present before application can run.

  1. Select a modality row to inspect its status.
  2. Open diagnostics when a modality is incomplete or has warnings. A Distribution shift warning means that the OOCV feature distribution differs substantially from the corresponding training modality in mean level, variance, missingness or training-referenced outlier burden. Review the modality before model application; the warning does not block import.
  3. Use the maintenance controls only when you intentionally need to replace, relink or re-import stored data.

Advanced details

DataIO records which OOCV modalities are available. The training/OOCV distribution check is a QC safety screen, not a statistical hypothesis test: it uses predefined discrepancy thresholds to surface potentially important domain shift. The application runner separately checks the modality requirements of the selected trained analysis.

Selected modality

This panel shows details about the modality selected in the overview.

  1. Click Show diagnostics to inspect warnings, missing values and source/import information.
  2. If the committed modality contains the wrong cases, features or labels, return to the modality manager and choose Modify selected.
  3. Correct the import setup, Preview again and recommit.
Advanced details

Data import task

Three NM2 words used below: A case is one observation that NM2 analyses—for example one person, participant, scan or sample. A modality is one block of measurements collected for a set of cases, for example questionnaire scores, MRI voxels, ROI values or connectivity edges. A feature is one input measurement that the machine-learning model uses.

This is the main sequence for adding one modality to NM2.

  1. Choose the Source type that matches where the data are stored.
  2. Choose Classification when the target is a class/category, or Regression when the target is numerical.
  3. Enter a short Description, for example “Baseline clinical variables” or “T1 MRI”.
  4. Use the source-specific panel to select the data.
  5. Assign Case IDs, features, labels and optional covariates.
  6. Complete the controls marked with red borders. Green borders indicate that the corresponding requirement is satisfied.
  7. Run Preview, inspect QC/diagnostics and correct any problem.
  8. Press Commit only when the Preview describes the dataset you intend to store.

Case IDs are identifiers that NM2 uses to recognise the same person, sample or scan across different files or data blocks.

Your responsibility: NM2 can validate structure and consistency, but you must decide whether the selected data and assignments are scientifically correct for your study.
Advanced details

The UI displays the readiness and validation state produced by DataIO. It does not create a separate scientific interpretation of the imported data.

Label definition

For classification, the label value tells NM2 which class each case belongs to. Use class names that clearly describe the groups shown later in Results Viewer.

  1. Select the label variable or column.
  2. Check the source class values that NM2 found.
  3. Enter clear names, for example Control, Depression and Psychosis.
  4. Verify that every name is attached to the correct source class value.

For regression, use a target name that describes the numerical outcome, for example Age or Symptom score.

Your responsibility: class names do not change the source labels. Make sure that the name you assign to each class describes the correct group.
Advanced details

Training classification data define the canonical class mapping. Label names are attached to those training-defined classes. Labelled OOCV data reuse the same training mapping.

Matrix/table import options

These settings control how matrix and table imports are interpreted.

  • Covariate handling — choose whether newly imported covariates are added to the existing covariates or replace them.
  • Validation mode — use the standard mode for normal imports; use enhanced diagnostics when you specifically need the additional checks.
  • Map text tokens to missing values — enable this when values such as NA, N/A or missing in the source mean “no value”.

After changing an import option, run Preview again.

Your responsibility: when you map a text token to missing data, make sure that the token is never used as a genuine scientific value in that column.
Advanced details

These options are applied after source retrieval and are shared by the relevant matrix/table import paths.

Advanced tabular filters

Use row filters when you want only selected rows to enter NM2, for example one visit, one site, or cases meeting a defined criterion.

  1. Open Advanced tabular row filters.
  2. Choose the table or worksheet that contains the filter column.
  3. Select the column, criterion and value.
  4. Click Add rule.
  5. Add further rules when needed.
  6. Choose AND when every rule must be true. Choose OR when at least one rule must be true.
  7. Click Apply filters, then run Preview.

Use is missing or is not missing when missingness itself is the criterion.

Your responsibility: check the Preview case count and case identities after filtering. A valid filter expression can still select the wrong study population.
Advanced details

Filters run before Case-ID uniqueness checks, case alignment and role materialisation. The filter column does not need to be used as a feature, label, covariate or Case ID.

Preview, QC and Commit

Preview lets you check what NM2 would import before anything is committed to the NM dataset.

  1. Complete the required controls and click Preview.
  2. Check the Import summary: the numbers of cases, features, labels and covariates should match what you expect.
  3. Open Diagnostics & QC and inspect data completeness, feature QC and case QC.
  4. If filtering or Case-ID matching was used, open Filtering and case-alignment details and confirm that the expected cases were retained.
  5. Read any red or orange diagnostic messages. Correct red blocking problems and run Preview again.
  6. Commit only when the Preview describes the dataset you intend to analyse.
Preview is read-only. It does not change the committed NM dataset.

What QC means

QC stands for quality control. NM2 summarizes missing values, lack of variation and unusually large feature values so that you can identify data that require inspection before modelling. A QC finding is not automatically an error and does not automatically exclude a case or feature.

Your responsibility: NM2 can report what it finds in the imported values, but it cannot decide whether an unusual value is scientifically valid. Review unexpected missingness, constant features and outlier patterns before Commit.
Advanced details

Preview creates and retains the current materialisation. QC consumes that retained materialisation. Commit reuses it while the relevant input settings remain unchanged; otherwise DataIO rematerialises through the same backend path.

Red and green borders

The coloured borders show the next required input or action.

  • Red border — required information or a required action is still missing.
  • Green border — that requirement is currently satisfied.
  • No coloured border — the control is optional, inactive, or is only a candidate selector while another control owns the required action.

Example: in Shared-key mode, selecting a Case-ID column does not apply it. The Apply shared key button stays red until you press it successfully.

Follow the red controls in sequence, but still read Preview/QC before Commit.

Advanced details

The borders display existing DataIO readiness/validation state. They do not replace backend validation and do not change scientific state by themselves.

Diagnostics & QC

This page is the final check of what NM2 understood from your import setup. Read it from top to bottom. You should be able to decide from this page whether the data are ready to Commit.

1. Import status

  • Green — no blocking problem was found. You still need to check the counts and QC results.
  • Orange — NM2 found one or more warnings. A warning does not block Commit by itself, but you should understand it before continuing.
  • Red — a blocking problem must be corrected before Commit.

2. Import summary

Confirm that the numbers match the dataset you intended to import:

  • Cases — the people, samples, scans or other observations that will enter this modality.
  • Features — the measurements that will be available to the machine-learning model. Depending on the modality these may be table columns, voxels, ROI values, connectivity edges or surface measurements.
  • Label targets — outcomes supplied for classification or regression.
  • Covariates — additional case-level variables such as age, sex or site.

Unexpected counts often indicate that the wrong source was selected, a filter removed unintended cases, or Case IDs did not match as expected.

3. Data completeness

  • Cases with no missing features — every feature has a value for these cases.
  • Cases with some missing features — at least one feature is missing and at least one feature is present.
  • Cases with all features missing — no feature value is available for these cases. These cases require particular attention.
  • Features with all values missing — the feature has no observed value in any case.
  • Constant features — the same observed value occurs in every case. Such a feature contains no variation for modelling.
  • Missing values (NaN) — the total number of values represented as missing in MATLAB. NaN means “Not a Number” and is the standard numerical marker used by NM2 for missing numeric values.
  • Infinite values (Inf) — values represented as positive or negative infinity. These are different from ordinary missing values and should normally be investigated.
  • Feature mean range and Feature SD range — the smallest and largest feature means and standard deviations. SD means standard deviation and describes how much a feature varies across cases.

Missing values are not automatically errors: later preprocessing can handle missing data in supported workflows. Nevertheless, completely missing cases or features and unexpectedly high missingness should be investigated before Commit.

4. Feature QC

Feature QC summarizes quality across the measurements. The default RMS feature z-score summarizes how strongly a case deviates from typical standardized feature values across the feature set; larger values indicate a stronger overall deviation pattern.

  • Features with missing values — how many features contain at least one missing case.
  • Constant / near-constant features — features with no, or almost no, variation.
  • Highest missing rate in one feature — the largest percentage of missing cases found in any single feature.
  • Highest outlier rate in one feature — the largest percentage of cases flagged as unusually far from the typical values of any single feature.

5. Case QC

Case QC looks at the same data from the case perspective:

  • Highest missing-feature rate in one case — the largest percentage of missing features found in any individual case.
  • Highest outlier-feature rate in one case — the largest percentage of features flagged as unusual for any individual case.

A high outlier rate is a signal to inspect the data. NM2 does not automatically declare the case or feature invalid.

6. Detailed QC rankings

Open this section to see the cases and features with the largest QC values. NM2 shows only a small highest-ranked subset on this page so that the browser remains responsive.

For very high-dimensional data, such as SNP or DNA-methylation data with hundreds of thousands or millions of features, NM2 displays summary statistics and the highest-ranked features instead of rendering every feature in the diagnostics page. This does not remove features from the import.

7. Filtering and case alignment

Open Filtering and case-alignment details when you used row filters or Case IDs. The tables show how many rows entered each step, how many cases matched, and whether rows were removed or added while the final case list was constructed.

8. Diagnostic messages

The message colours tell you how to interpret each entry:

  • OK / green — a check or processing step completed successfully.
  • Info / blue — NM2 records what it found or did.
  • Warning / orange — review the finding before continuing.
  • Error / red — a blocking error must be corrected before Commit.

Use the message filters to show only errors, warnings, information or successful checks. Repeated identical messages are collapsed into one entry. Open Technical details when you need the internal source name or complete backend message for troubleshooting.

Your responsibility: a technically valid import can still contain the wrong scientific data. Before Commit, confirm that the case identities, feature counts, labels, covariates and QC patterns are plausible for your study.

When asking for support, open Technical details and copy the complete message, including the source and any stack information.

Advanced details

Diagnostic severity is assigned by backend source discovery, materialisation, validation, QC and Commit paths. The browser does not reinterpret blocking state. For large feature spaces, full feature-level QC vectors are deliberately not transferred to or rendered by the browser once the configured response limit is exceeded; compact summaries and top-feature lists remain available.

Case QC viewer

The Case QC viewer lets you inspect one case at a time after Preview has computed QC. Case: shows the Case ID that identifies the case currently displayed.

  • Use the left and right arrow buttons to move to the previous or next case.
  • Use Previous QC-flagged or Next QC-flagged to jump only between cases that NM2 recommends for review.
  • QC-flagged means that the case reaches the current QC review threshold, or that all feature values are missing, or that the case is constant. It is a review aid only.
  • A QC-flagged case is not automatically excluded. Inclusion remains an explicit import decision.
  • From Detailed QC rankings, click Inspect to open that Case ID directly in the appropriate viewer.

The central display depends on the data representation. Tabular non-imaging data use the feature-QC viewer. Moderate tabular data show an exact feature profile; very high-dimensional tabular data open with a distribution histogram, where highlighted tail bars identify unusual z-score ranges and selecting a bar lists a bounded set of exact matching features. An optional Ordered feature overview is useful only when column order itself has scientific or technical meaning. Volumetric data, surface/vertex data and connectivity data keep their dedicated QC viewers. ROI/parcellated QC vectors are projected onto their configured sMRI atlas/template or surface annotation and never enter the tabular profile/histogram pipeline. A case viewer offers only case-level QC maps or matrices. Group-level QC statistics are available only in the separate group QC viewer. In volumetric group QC, NM2 uses the retained group mean structural image as the anatomical background and overlays the selected group QC statistic; the group outlier-rate map is defined by the displayed |z| threshold.

Your responsibility: QC identifies unusual data patterns but cannot determine whether they are scientifically valid. Inspect the source data and study context before excluding a case.
Advanced details

QC-flagged navigation is derived from the retained Preview QC case metrics. It does not create or persist a separate flagged-case state and does not change imported scientific data.
