Choose the source data

Three NM2 words used below: A case is one observation that NM2 analyses—for example one person, participant, scan or sample. A modality is one block of measurements collected for a set of cases, for example questionnaire scores, MRI voxels, ROI values or connectivity edges. A feature is one input measurement that the machine-learning model uses.

Use this source when the data are already loaded in MATLAB as vectors or matrices. For a feature matrix, one row must represent one case and one column must represent one feature.

  1. Make sure the required variables exist in the MATLAB base workspace.
  2. Choose MATLAB workspace variables as the Source type.
  3. Click Refresh workspace variables.
  4. Assign the variable(s) that contain features, labels and optional covariates.
  5. For every feature matrix, make sure that rows are cases and columns are features.
  6. Choose how NM2 matches the rows across the selected variables, then run Preview.

If your data are stored in a MATLAB table, use the dedicated MATLAB tables source instead.

Your responsibility: NM2 uses the matrix orientation you provide. Before import, verify that rows represent cases, columns represent the intended features, and any separate Case-ID vector describes those rows in the same order.
Advanced details

Workspace matrix import reads the selected base-workspace variables and then passes them to the common DataIO role-assignment, alignment, label and materialisation logic.

Case alignment

When features, labels or covariates are stored in separate MATLAB vectors or matrices, NM2 must know which rows belong to the same case.

For workspace and MAT-file matrix imports, choose one of these modes:

  • Key per block — choose this when each feature, label or covariate block has a Case-ID vector that identifies its rows.
  • Explicit row order — choose this only when every input block has exactly the same number of rows and row 1, row 2, and so on refer to the same cases in every block.

When this is the first modality in a training or OOCV dataset, also choose how NM2 creates the initial case list:

  • Complete-case intersection keeps only cases that are present in every required input block.
  • Target-anchored uses the cases present in the label/target data as the reference list.
  • Feature union keeps the union of cases found in the feature blocks; blocks that do not contain a retained case contain a missing value for that case.
Your responsibility: choose the alignment mode and case-list policy that match how your MATLAB data are actually organised.
Advanced details

Key per block matches rows by the Case-ID values assigned to each data block. Explicit row order does not perform identifier matching. The first-case-axis policy applies only when a new case list is created; later modalities are matched to the existing list.

Shared key

Shared key is not used for this source type. Use the Case-ID controls or alignment options shown for this source instead.

Advanced details

Shared key is the tabular mode for data in which the same Case-ID column(s) exist in every selected table. This source establishes case identity through its own Case-ID controls before the data enter the common DataIO matching path.

Key per block

Use Key per block when each MATLAB feature matrix, label vector or covariate matrix has a Case-ID vector that identifies its rows.

  1. Choose Key per block.
  2. Assign the feature, label and optional covariate variables.
  3. For each assigned data block, select the Case-ID vector that belongs to that block.
  4. Check that the Case-ID vector has one value for every row in its data block.
  5. Run Preview and check the number of matched cases.
Your responsibility: each Case-ID vector must describe the rows of the data block to which you assign it. NM2 uses those values exactly for matching.
Advanced details

Each matrix/vector block is matched through its assigned Case-ID vector. The names of the Case-ID variables do not need to be identical; their values define the correspondence.

Explicit row order

Explicit row order assumes that all MATLAB vectors and matrices providing input data have exactly the same number of rows and that each row refers to the same case in every variable. For example, row 1 must refer to the same person in every feature, label and covariate block, row 2 to the same person, and so on.

  1. Choose Explicit row order only after you have verified this row correspondence.
  2. If NM2 shows the Case-ID/PSN selector, choose the variable that identifies each row. PSN is the legacy NM2 name for the Case ID.
  3. Run Preview and confirm the expected number of cases.
Your responsibility: make sure that these assumptions are met by the data. NM2 does not compare identifiers in this mode.
Advanced details

Explicit row order bypasses Case-ID matching and retains the supplied row order exactly.

Row filters

The Advanced tabular row filters panel is not used for this source type.

If cases must be excluded, select the required files/cases in the source-specific controls or prepare the source data before import. Then run Preview and check the final case list/count.

Advanced details

Tabular row filters operate on tables and worksheets. Image, connectivity, surface and other non-tabular sources use their own case/file selection and then enter the common downstream DataIO alignment and validation path.

Labels

Labels are the values that you want the model to predict.

  • For classification, every labelled case belongs to a class, for example Control / Patient or Class A / Class B / Class C.
  • For regression, every labelled case has a numerical target, for example age or symptom score.
  1. Select the variable or column that contains the labels when labels are required for this import.
  2. For classification, check the source values that NM2 found and enter clear class names in the Label definition panel.
  3. If the labels are matched by Case ID, also select the Case-ID variable that identifies the rows of the label data.
  4. Run Preview and check the class counts or target summary.

Leave genuinely missing labels missing. Do not replace them with an invented class or numerical value.

Your responsibility: for classification, make sure that each class name is attached to the correct source label value.
Advanced details

Training classification data define the raw source value → canonical NM2 class mapping once. Labelled OOCV data use the same training mapping. Missing labels remain NaN. An OOCV class value that was not present in training is a blocking error.

Covariates

Covariates are optional case-level variables that NM2 stores separately from the main features, for example age, sex, site or scanner.

  1. Select the covariate variable(s) or columns if your analysis needs them.
  2. Enter covariate names when they are not already available from table headers.
  3. If covariates are matched by Case ID, also select the Case-ID variable that identifies their rows.
  4. Choose whether the new covariates are added to the existing covariates or replace them.

Leave the covariate assignment empty when the analysis does not use covariates.

Advanced details

Covariates are committed as a separate case-level matrix. Missing covariate values are retained and reported. Downstream preprocessing or analysis determines how those missing values are handled.

Preview

  1. Complete the controls marked as required, then click Preview.
  2. Check the number of cases and features that NM2 plans to import.
  3. Check the preview table and the class/target summary when labels are present.
  4. Open diagnostics and QC when NM2 reports a warning or blocker.
  5. If anything is wrong, correct the setup and run Preview again.
Preview does not change the committed NM dataset. It shows the data that NM2 will import if you press Commit with the current settings.
Advanced details

Preview materialises the current import setup and retains that result. Commit reuses the retained materialisation while the relevant import settings remain unchanged, which avoids unnecessary rereading of the source.

QC and diagnostics

Use QC and diagnostics to check the data before Commit.

  • Blocking: the stated problem must be corrected before Commit.
  • Warning: the warning itself does not block Commit, but read it and decide whether the data are scientifically acceptable.
  • Information: NM2 is reporting what it found or what it did.
  1. Read the first blocking message, if one is present.
  2. Identify the named file, table, variable, case or setting.
  3. Correct that item in the import setup.
  4. Run Preview again and re-check QC.
Your responsibility: a technically valid import is not automatically scientifically correct. Check that the cases, variables and labels are the data you intended to import.
Advanced details

Diagnostics are produced by backend source discovery, materialisation, validation and QC. The QC viewer uses the retained Preview materialisation rather than independently rereading the source.

Commit

Commit writes the Previewed data into the selected NM2 training modality or OOCV dataset.

  1. Run Preview and resolve every blocking diagnostic.
  2. Check the case count, feature count, labels and QC information.
  3. Click Commit only when these values describe the dataset you intend to create.
  4. Return to the modality overview and verify that the modality is listed and ready.
Your responsibility: Commit confirms that the current import setup is scientifically the one you want to store in NM2.
Advanced details

Commit transfers the validated retained materialisation into NM2 and stores the restorable scientific input settings and source description. If the retained Preview is no longer valid, the same DataIO materialiser runs again before Commit.

Modify / Resume

Use Modify to reopen the setup of a modality that has already been committed. Use Resume to continue an import task that was saved before Commit.

  1. Open Modify or Resume.
  2. Check the restored source, the feature/label/covariate/Case-ID assignments, the alignment settings and the filters.
  3. Re-enter live information that NM2 intentionally does not save, such as a database password.
  4. For database imports, rediscover the database/schema/table list before continuing.
  5. Run Preview again before recommitting.

Do not assume that a value shown after Resume proves that the external source is currently connected. Follow the red/green navigation borders and refresh live resources when requested.

Advanced details

Persisted scientific settings are rehydrated from DataIO state. Security-sensitive credentials and live external namespace catalogues are not persisted.

OOCV / application data

OOCV (out-of-cross-validation) data are independent cases to which an already trained model is applied, for example an external validation cohort or new clinical cases.

  1. Create or select the OOCV/application dataset.
  2. State whether true labels are available for these cases.
  3. Import the modality or modalities required by the trained analysis.
  4. Use the same scientific meaning and feature definition as in training.
  5. Preview and Commit each OOCV modality.

The OOCV dataset does not need the same number of cases or the same class proportions as the training dataset. If labels are present, their class values must correspond to classes that existed in training.

Your responsibility: make sure that each OOCV feature has the same meaning, units and preprocessing interpretation as the corresponding training feature.
Advanced details

Training defines the classification class mapping. Labelled OOCV data reuse that mapping. DataIO can store an OOCV dataset while only some modalities are present; the selected trained analysis determines which modalities are required before application can run.

Public API

If you are importing data through the graphical DataIO interface, you can ignore this section. The public API is for reproducible MATLAB scripts that perform the same imports without clicking through the interface.

Advanced details

The browser and public API converge on the same DataIO authorities. Example:

spec = struct('sourceType','workspace','modeflag','classification', ...
    'description','Clinical predictors','variableRoles',roles, ...
    'metadataAlignmentMode','key_per_block');
[NM,out] = NMDataIOAPITools.importTrainingMatrix(NM,spec);

Use the exact fields supported by NMDataIOAPITools for production scripts.
