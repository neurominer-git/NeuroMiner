Model visualization and permutation testing

How NeuroMiner evaluates model-weight patterns and selects components for visualization.

Overview Input-space test Permutation mode Model-space test P-value correction Significance threshold

What do these settings do?

Visualization examines patterns of feature weights learned by prediction models. A large weight describes a strong contribution within the fitted model, but does not by itself establish statistical significance or reproducibility.

Permutation testing compares observed patterns with a reference distribution obtained by repeating the analysis after permuting selected information. The input-space test examines feature-weight patterns; the model-space test evaluates components of a dimension-reduced model before selected components are projected back into the original feature space.

The model-space controls appear only when the preprocessing pipeline contains an eligible dimensionality-reduction or component-removal step.

Input-space permutation test

Tests model-weight patterns in the original input-feature space. The permutation procedure provides a reference distribution against which observed feature weights can be assessed.

When model-space component testing is also enabled, the input-space test provides an additional test of the back-projected feature map.

Perform permutation test in input space

Enables or disables permutation-based inference for the input-space feature weights. With this option off, an input-space permutation test is not requested; the displayed weights remain descriptive rather than permutation-significance estimates.

Number of permutations

Sets how many randomized analyses are used to construct the reference distribution (default: 5000). More permutations increase computation and provide finer resolution for empirical significance estimates.

The same permutation count is displayed in the input-space and model-space sections. Changing either field changes the shared count.

Permutation mode

Specifies which information is randomized when constructing the null distribution:

  • Labels: rearranges the outcome labels relative to the predictor data.
  • Features within label: permutes feature values within each outcome group while retaining the group labels.
  • Labels and features: permutes both outcome assignments and feature information.
  • Covariate(s): permutes selected covariates. This mode is available when covariates are present and the relevant expert settings allow it.

These modes define different reference distributions and therefore different statistical questions about the model-weight pattern.

Covariates to permute

Selects the covariate columns whose values are randomized in the Covariate(s) permutation mode. This tests the influence of the selected covariate information on the analysis, including any preprocessing steps that depend on it.

The selector is shown only when covariate permutation is active. Multiple covariates can be selected.

Model-space permutation and back-projection

When a model is trained on lower-dimensional components, the feature map can be reconstructed from the component weights and their original-feature loadings. Different components may contribute patterns that partly cancel when combined into one map.

Model-space permutation testing evaluates components before reconstruction. Only components meeting the selected significance criterion are included in the resulting back-projected map.

Perform model-space permutations and back-project significant components

Enables component-level permutation testing and selective back-projection into the original feature space. The component-significance test determines which components contribute to the resulting map.

This option is available when the preprocessing pipeline provides the component representation needed for back-projection. It is separate from the optional input-space permutation test.

Number of permutations for component testing

Displays and edits the same permutation count used by the input-space test. The number determines how many randomized analyses support the component-significance assessment.

Editing this field also updates the count shown in the input-space section.

Component P-value correction

Specifies how multiple component tests are accounted for when deciding which components are retained:

  • FDR before back-projection, each model separately: adjusts component P values within each model before selecting components for reconstruction.
  • FDR after cross-validation, globally: applies the correction to component significance after aggregation across cross-validation results.
  • No correction: uses uncorrected component P values for selection.

False discovery rate (FDR) correction controls the expected proportion of false discoveries among the findings declared significant under its statistical assumptions. The selected correction changes which components pass the threshold and therefore which patterns enter the back-projected map.

Significance threshold for back-projection

Sets the component-significance cutoff (default: 0.05). Components meeting the selected criterion contribute to the back-projected feature map; the others are omitted.

The field is labeled q for the per-model FDR option and α for the global-FDR and uncorrected options. A smaller threshold selects fewer components at a given set of observed significance values.
