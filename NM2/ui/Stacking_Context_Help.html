Start here: what is stacking?

Ordinary machine learning starts with measurements such as clinical variables or imaging features. Stacking starts with predictions made by other, already trained analyses. Their outputs become the input features of a new second-level (meta-)learner.

Original predictors → first-level models → prediction scores → second-level model → final prediction

Example. You have completed one analysis on clinical variables and another on MRI data. Rather than combining their original measurements, you can train a second-level learner using each analysis's prediction score as an input. This lets the new learner learn how to combine their complementary information.

Combining prediction scores can exploit information from different models. Highly similar scores may add little information, while fitting a second-level model introduces another opportunity for overfitting.

The controls below specify which analyses supply scores, how those scores are named, and whether the scores originate from CV1 training or CV1 test cases. CV1 test predictions are the default.

Activating stacking using predictions generated by other analyses

Disabled: the template uses its ordinary modality-based learning setup. Enabled: the template uses predictions from selected first-level analyses as the features for a second-level model.

The analysis-selection dialog requires at least two completed first-level analyses with compatible cross-validation (CV) partitions.

Each selected analysis supplies prediction-derived features. Analyses trained on different information sources may supply complementary signals; highly correlated predictions may add little independent information.

Stacking changes the meaning of the entire training template: its preprocessing and machine-learning settings now concern the prediction-score features, not the original clinical or imaging variables.

First-level analyses entering the stacker

The Select analyses... dialog lists completed first-level analyses. At least two must be selected; ineligible analyses cannot be selected, for example when training is incomplete or CV partitions are incompatible.

Each selected analysis contributes one or more prediction-derived features. The displayed feature count is the number of input columns the stacker will receive; it need not equal the number of selected analyses.

The stacker combines the selected prediction sources. Similar sources can produce correlated input columns; models trained on distinct information can produce different scores for the same case.

An unavailable entry cannot contribute stacking features. The selector admits only eligible analyses and enforces the minimum selection count.

Feature-name extraction

Feature names label the columns of the stacking input and appear in coefficients, feature rankings and visualizations of the second-level model.

Automatically from selected analyses (default): feature labels are derived from the selected first-level analyses.

Manually from MATLAB workspace variable: the next field identifies a workspace variable containing labels for the prediction features.

Names change only the annotation, not predictions or feature values. A stacker feature represents a first-level prediction, not an individual original clinical or imaging predictor.

Workspace variable containing feature names

Manual naming takes the name of a variable in the MATLAB base workspace, for example stackerFeatureNames. The input is a variable name, not a filename or a list of labels.

The workspace variable contains a cell array of feature names, one per stacking input column in the same order. The names are used in feature-level outputs.

When two analyses each contribute one score, an example is stackerFeatureNames = {'Clinical model','MRI model'};. When an analysis contributes several scores, the cell array also needs a name for each additional score.
A variable that is missing or is not a valid label cell array cannot supply manual names. Automatic naming derives the labels from the selected analyses instead.

Extract predictions from

This choice determines whether the stacker receives first-level model predictions for CV1 training cases or for CV1 test cases. The two types of scores differ in how they were generated.

CV1 test data (default): predictions are generated for cases excluded from fitting the corresponding first-level model. They are out-of-fold predictions at the first level.

CV1 training data: predictions are generated for cases used to fit the corresponding first-level model. Such in-sample scores can appear more accurate than predictions for new cases, so the second-level learner receives a different score distribution.

CV1 test predictions may contain patterns specific to the particular inner test folds. The second-level learner can overfit to these patterns, especially with flexible model optimization or wrapper-based feature selection. This can reduce generalizability to the independent CV2 test cases. CV2 remains excluded from training and selection by the nested CV procedure.

After choosing the stacking inputs

  1. Stacking preprocessing. Its operations transform first-level prediction scores, not the original clinical or imaging measurements.
  2. Second-level learner. Its algorithm and hyperparameters act on the stacking feature table. Greater model flexibility may fit more patterns in these scores, including noise.
  3. CV evaluation. The outer CV2 test cases remain excluded from training and selection. CV2 evaluates the full two-level procedure on its held-out cases.
  4. Feature interpretation. Feature importance in the stacker describes the contribution of first-level prediction sources, not individual original clinical or imaging predictors.

With stacking enabled, ordinary data fusion is disabled. The stacking pipeline operates on prediction-score features rather than concatenating the original clinical or imaging matrices.

Applying a stacker to an external cohort (OOCV)

You can apply a trained stacker to an independent external cohort (OOCV) if predictions from every selected first-level analysis are available for the same external cases.

Application sequence: import the external cohort and apply each selected first-level analysis to obtain its prediction scores. These scores then form the inputs to the trained stacker. The stacker can be applied only where all required first-level prediction features are available.

OOCV applies the trained first-level and second-level models to external data. The application uses fitted preprocessing settings and does not use external outcomes for model fitting.

What the Stacking choices determine

  • At least two eligible analyses are required by the selection dialog; each contributes one or more prediction features.
  • CV1 training scores are in-sample first-level predictions; CV1 test scores are out-of-fold first-level predictions.
  • Feature labels name the prediction sources; they do not change the data.
  • Preprocessing and learner settings apply to the stacked prediction-score features.
  • OOCV stacking requires first-level predictions for every input feature of the stacker.
