Interpretable ML: explaining model predictions

How feature replacement changes predictions, and how to define the features and reference values used.

Start here: interpreting individual predictions

Interpretable machine learning (MLI) estimates how a trained model’s prediction changes when selected input features are replaced with reference values. The difference between the original and modified predictions describes the model’s sensitivity to those features for a particular case.

Feature changes may be evaluated one by one or in subsets. The resulting prediction changes are model explanations: they describe the fitted model’s response to modified inputs, not a causal effect of the measurements.

The four tabs specify how inputs are modified, which features are eligible, how prediction changes are scaled, and—for imaging data—whether modifications act on atlas-defined regions.

Method: how are features modified?

Each occlusion iteration replaces a selected subset of features and compares the model prediction before and after replacement. The method determines which replacement values are used.

Feature subsets are sampled from the eligible feature space. Their size is set by the feature-fraction control or, when atlas binding is active, by the corresponding fraction of atlas regions.

Interpretation method

Upper/lower percentiles: replace selected feature values with upper and lower percentiles of the training distribution. Median: replace them with the training median.

Median-span flip: shift feature values across the training median by a median-quantile amount. Median-mirror: mirror values around the median. These methods change the input according to its position in the training distribution.

Random-value occlusion: draw replacement values from the feature’s training distribution. Shapley values: estimate contributions by comparing predictions across feature coalitions, with training samples serving as reference inputs.

Replacement methods define different questions about the fitted model. For example, extreme-percentile replacement probes responses to relatively large feature changes; median replacement probes responses to typical training values.

Upper percentile

For upper/lower percentile occlusion, this sets the upper reference percentile of each feature’s training values (default: 95). A value of 95 uses the 95th percentile, not the numeric value 95.

This field is used only with the upper/lower percentile method.

Lower percentile

Sets the lower reference percentile of each feature’s training values (default: 5). Together with the upper percentile, it determines the range of perturbations used to assess prediction changes.

This field is used only with the upper/lower percentile method.

Number of iterations

Specifies how many feature subsets or coalitions are evaluated. The default is 1024. Increasing this number explores more combinations and increases computation.

For methods that use unique fixed-size subsets, the number may be reduced when fewer distinct combinations exist than requested. Inf selects automatic stopping for non-Shapley methods; the minimum-visit and maximum-iteration fields then become available.

A separate feature-selection step determines which input features are eligible. This field governs how often those eligible features are perturbed, not how many original features are retained in the model.

Fraction of features visited per iteration

Fraction between 0 and 1 specifying how many eligible input features are changed together in each iteration (default: 0.10). For example, 0.10 changes approximately one tenth of the eligible features at a time.

If a visualization map restricts the feature space, the fraction applies to the remaining eligible features. With atlas binding, it applies to the atlas units selected for modification.

This control is not used for Shapley values.

Minimum visits per feature

In automatic-stopping mode, sets the target minimum number of times each eligible feature should be included in a perturbation (default: 100).

The process stops after the visit target has been reached or after the maximum number of iterations. This field appears when the iteration count is Inf for a non-Shapley method.

Maximum iterations

Upper bound on the number of perturbation iterations in automatic-stopping mode (default: 1000). It limits the computational effort even if some features have not reached the requested minimum number of visits.

This field appears when the iteration count is Inf for a non-Shapley method.

Fraction of training samples visited per iteration

For Shapley values, sets the fraction of training examples used as reference samples for feature replacement (default: 0.25).

These samples form the background against which a case’s feature contributions are estimated. A larger fraction uses more training examples per iteration and increases the amount of computation.

Feature-space restriction: which features are perturbed?

A visualization map can restrict interpretation to a selected subset of features. Only features passing the chosen map criterion are eligible for modification.

The map restricts the explanation space; it does not retrain the predictive model or replace its original inputs.

Use map from model visualization

Enable this option to use a map produced by the model-visualization analysis to select features for MLI. The next controls determine which map and which values meet the inclusion criterion.

With the option disabled, MLI operates on the available feature space without this visualization-map restriction.

Map type

Cross-validation ratio: expresses the stability of estimated feature weights relative to their variability across cross-validation models.

Sign-consistency P value, uncorrected: describes evidence that a feature’s weight direction is consistent across models. FDR-corrected P value: applies false-discovery-rate adjustment across features.

The map type determines how the cutoff value should be interpreted: a cross-validation ratio has different units and direction from a P value.

Cutoff value: one or two numbers

Enter one threshold (for example 2) or two thresholds separated by a space (for example -2 2).

One number is compared with the selected map using a single operator, such as greater than. Two numbers specify a lower/upper interval; the available operators then describe whether to include values inside or outside that interval.

The cutoff is interpreted as an actual map value in absolute mode or as a percentile boundary in percentile mode.

Cutoff mode

Absolute: compare map values directly with the specified cutoff. For example, a cross-validation ratio cutoff of 2 refers to a ratio of 2.

Percentile: interpret the cutoff as a percentile boundary of the selected map values. This selects features by their relative position in the map distribution rather than a fixed map value.

Cutoff operator

Specifies the comparison used to include features. With one cutoff, the choices are <, ≤, >, ≥, = and ≠.

With two cutoffs, each operator is a pair of comparisons at the two boundaries: <, >; ≤, ≥; >, <; or ≥, ≤. The feature map is evaluated against both cutoff values. For example, <, > includes values below the first or above the second cutoff.

Normalization: how are prediction changes displayed?

MLI produces prediction-change estimates for each case and feature. Case-level normalization changes how these estimates are scaled relative to other features within the same case.

This control is not available for Shapley values.

Normalize prediction-change estimates at the case level

Group-level only: retain the prediction-change estimates without further case-level rescaling. Mean centering: subtract the case’s mean prediction change across features.

Z-normalization: center and divide by the case’s standard deviation across features. Scale to [−1, 1]: rescale the case-level values to that range.

Case-level normalization changes the relative scale shown for each case. It does not change the fitted predictor or its original predictions.

Atlas binding: modify brain regions together

For imaging data, atlas binding replaces changes to individual voxel or surface features with modifications of features belonging to an atlas-defined region.

The atlas image identifies regions numerically; the descriptor table associates those numeric IDs with region names. Atlas resources must be imported into the active interpretation configuration.

Bind data modification to neuroanatomical atlas

Enable atlas binding to perturb all eligible imaging features belonging to a selected atlas region together, rather than changing individual features independently.

The selected atlas must correspond to the feature space of the current imaging modality. Atlas binding is offered only for imaging modalities.

Atlas imaging file

Select a volume or surface atlas file containing a numeric region identifier for each location. The atlas defines which imaging features belong to each region.

Select and import atlas image... chooses a file and imports it. Import current atlas image imports the path already shown in the text field. After changing a path manually, importing the file is necessary to construct its feature-to-region mapping.

Atlas descriptor file

Select a text table that associates numeric atlas region IDs with their region descriptions. The table usually contains a column of IDs and a column of region names.

Preview current descriptor file shows the raw header and how MATLAB interprets the columns with the current delimiter. Import descriptor table reads the two selected columns into the atlas configuration.

The region IDs must correspond to the atlas image labels; otherwise the named regions will not describe the intended image locations.

Descriptor delimiter

Specifies how columns are separated in the atlas descriptor file: semicolon, comma, tab or whitespace.

Changing this value changes how the header and region columns are parsed. The descriptor preview displays the resulting column names before import.

ROI ID column

Name of the descriptor-table column that contains the numeric atlas region identifiers (default: ROIid). These IDs link rows of the descriptor table to labels in the atlas image.

Enter the table column name, not an example ID value or a column number.

ROI descriptor column

Name of the descriptor-table column that contains the region names (default: ROIdesc). The labels appear in region-level interpretation output.

Enter the table column name as shown in the descriptor preview.
