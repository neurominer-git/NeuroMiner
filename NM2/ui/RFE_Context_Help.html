Overview

Do I need ensemble learning?

Neither option is required for ordinary model training. When Use filter-based ensemble generation and Use wrapper-based ensemble generation are both off, the learner receives the features produced by the preceding preprocessing steps without these additional selection strategies.

A filter ranks features by a relevance rule. A wrapper evaluates feature subsets through predictive model performance. Both can be used to generate alternative feature selections.

The filter and wrapper switches are independent. Each enabled strategy adds feature-selection operations to the analysis.

The four sections are Overview, Filter strategy, Wrapper strategy and CV2 / ensemble prediction. Strategy-specific pages appear only after enabling the corresponding checkbox.

Feature stability across CV1 partitions

Feature stability summarizes how consistently a feature is selected across different CV1 partitions. The Filter and Wrapper stages have separate feature-stability settings.

Feature-stability comparisons require the same feature coordinate axis across CV1 partitions. Preprocessing that changes this axis makes feature-stability analysis unavailable.

When the feature coordinate system changes, the configurator clears the incompatible stability setting; other Filter and Wrapper settings remain unchanged.

Filter strategy

What does a filter do?

A filter scores features according to a selected relevance or ranking rule. It can select or arrange features before the predictive learner fits the resulting model. It does not search the feature space by repeatedly training the final learner in the way that a wrapper does.

  1. Enable Use filter-based ensemble generation on Overview.
  2. Choose a filter method.
  3. Decide whether to retain one selected set or evaluate alternative feature subsets.
  4. Adjust method-specific settings only if needed.
NeuroMiner evaluates filter-based feature selection within the relevant cross-validation training partitions; CV2 test cases remain excluded from selection.

Decision source for ensemble construction

Hard decisions use the predicted class labels; soft decisions use the model’s continuous scores. Scores can retain confidence information that is lost when predictions are converted to labels. This choice matters only when a filter ensemble is constructed.

Multiclass ranking mode

Pairwise ranks features separately for each binary class contrast. Multi-group evaluates the classes together. This setting applies only to multiclass classification.

Filter method

The Filter method defines how each feature is ranked or scored for selection. Methods differ in their association, information-theoretic, margin-based or neighborhood criteria.

  • Pearson/Spearman: rank features by their relationship with the target, using a linear or rank-based association measure.
  • MRMR: balance target relevance against redundancy between selected features.
  • FEAST: information-theoretic feature selection; some methods require additional feature-count settings.
  • Random subspace sampling: explore multiple randomly chosen feature subsets.
  • Relief: evaluate features using nearby observations.

The selected method determines which additional controls appear. Available methods also depend on whether the analysis is classification or regression.

Advanced: method-specific parameters

Depending on the method, feature counts, iterations, starting points, distance measures or neighborhood sizes control the search process.

One feature set or several?

Use feature subspaces lets the filter consider several candidate subsets instead of one ranking cutoff. With subspaces off, the page shows the rank-based threshold controls. With subspaces on, choose how candidate feature sets are selected and possibly combined.

Minimum number of features sets a lower bound for a selected set. Rank threshold applies when rank-based selection is being used. Only the controls relevant to the selected subspace mode are displayed.

Evaluate feature subspaces

Enabled: construct and evaluate multiple candidate subsets of different sizes within CV1. Disabled: use a single rank threshold. The first option is more computationally expensive but permits subset-size selection inside CV1.

Minimum number of features

Lower bound on the size of ranked candidate subsets when subspace evaluation is enabled. For example, 5 prevents the subspace search from considering a subset containing fewer than five features; it does not force every ranking algorithm to output five features.

Rank threshold (percentile)

Used only when subspace evaluation is off. For a ranked list of k features, the threshold selects the feature at rank k − ceil(k × threshold/100). With 100 features and a threshold of 95, this is rank 5—not all five top-ranked features and not 95% of features.

Performance data for selecting subspaces

Training criterion scores subsets on CV1 training cases; test criterion uses the held-out CV1 fold; training + test considers both.

Subspace selection strategy

Winner takes all selects the best-performing subset; within range keeps subsets near the optimum; percentile cutoff retains candidates meeting a specified performance percentile; all subspaces keeps every candidate. The latter options enable construction of an ensemble from several subsets.

Range or percentile of eligible subspaces

Active for “within range of optimum” or “percentile cutoff.” In range mode this controls how close a candidate must score to the best result; in percentile mode it defines the performance cutoff. Winner-takes-all and all-subspaces modes do not need this field.

Subspace stepping

Controls the percentage of the maximum feature count moved between successive subset sizes. Small steps test more subset sizes and cost more computation; 0 uses the established default stepping behavior.

Combining filter-selected models

When feature subspaces are enabled, advanced ensemble controls may become available. Use them to choose one candidate feature set or combine models built from several sets.

Subspace selection strategy controls which candidates qualify. Ensemble construction controls how qualifying candidates contribute to the final ensemble. Options can include performance-based selection, diversity-based selection, feature-agreement rules or boosting.

Some choices reveal extra settings such as minimum ensemble size, agreement percentage, a diversity criterion, or boosting iterations.

Advanced: performance and diversity

Performance measures predictive accuracy; diversity measures differences between candidate predictions. Ensemble optimization can use both. Regression and classification expose different diversity measures.

Subspace ensemble construction

After the eligible subsets have been selected, choose whether to build an ensemble, optimize performance and diversity, derive a consensus feature mask, or combine predictions by boosting. “None” leaves ensemble construction inactive.

Minimum number selected

Lower bound on the number of classifiers or features retained for ensemble construction. In consensus-feature mode this is a feature-count constraint; in classifier ensemble modes it limits how small the ensemble can become.

Feature-agreement percentage

For consensus-based feature extraction, this is the required percentage of eligible subspaces that must contain a feature. At 75%, a feature needs to appear in at least three out of four subspaces.

Diversity measure

Defines how differently candidate classifiers behave. Vote entropy measures disagreement; kappa, Q and double-fault choices compare prediction agreement/error patterns. Diversity is meaningful only when several classifiers contribute.

Hard labels or soft scores

Choose between discrete predicted labels and continuous learner scores for combining base learners. Score-based decisions retain more information but depend on the scale/calibration of model scores.

Base-learner weighting

No weighting gives each selected classifier equal weight. Inverse resubstitution error gives lower-error training classifiers greater weight.

Diversity rank-blend weight

When performance and diversity are combined, adjusts how strongly the diversity ranking influences candidate selection. Higher values put more weight on diversity; this does not change individual feature ranks.

Ensemble size penalty

Discourages excessively large classifier ensembles during optimization. Zero disables the penalty; increasing it favours smaller sets at otherwise comparable performance and diversity.

Early-stop patience

Number of search steps without improvement allowed before ending ensemble optimization. Zero disables this stopping rule. More patience searches longer and can be slower.

Diversity tolerance ε

Tolerance used in diversity-focused ensemble selection: differences smaller than this are treated as approximately equivalent. Larger values make the diversity criterion less discriminating.

Boosting objective

Ridge/MSE finds linear combination weights by squared-error fit; log-loss optimizes a probabilistic classification loss; exponentiated gradient iteratively updates nonnegative weights. Regression is constrained to the ridge option.

L2 penalty λ

Regularizes the combination weights to reduce unstable, extreme coefficients. Larger values shrink weights more strongly. This setting is separate from the learner’s own regularization.

Diversity weight α

Weight given to prediction diversity in the boosting objective. Zero disables the diversity contribution; positive values trade off predictive fit against similarity between base learners.

Low-weight threshold

Weights below this cutoff are treated as negligible when choosing contributing models. Increasing the cutoff may yield a sparser ensemble.

Use logits

For classification, transform probabilities to log-odds before fitting combination weights. Use only when the base predictions have a meaningful probability interpretation.

Probability clipping

In log-loss mode, keeps probabilities away from exactly zero or one before taking logarithms. Prevents infinite loss; too-large values distort confident predictions.

Exponentiated-gradient step size η

Controls how far ensemble weights move at each exponentiated-gradient update. A higher value adapts faster but can oscillate; active only in exponentiated-gradient mode.

Exponentiated-gradient iterations

Maximum number of exponentiated-gradient weight updates. More iterations allow a longer search at greater computational cost; unused in ridge or log-loss mode.

Share weights across classes

For multiclass decompositions, use a shared set of ensemble weights rather than optimizing separate weights for each dichotomizer. Active only for exponentiated-gradient classification.

Boosting diversity metric

Choose the classifier disagreement measure used for boosting when diversity weight α is positive. If α is zero, this choice has no effect on the objective.

Regression diversity kernel

Defines how regression-model residuals enter the diversity penalty: covariance, correlation or Laplacian similarity. Used only for regression boosting with a positive diversity weight.

Kernel diagonal handling

Choose whether self-similarity entries of the regression diversity kernel are set to one, to zero, or retained. This changes how much the penalty includes each model’s own residual variation.

Kernel scaling

Set the diversity kernel to unit norm or scale it relative to the prediction matrix (HHT). Scaling determines the magnitude of the diversity penalty relative to the fit term.

Automatic regression diversity weight

Let the regression boosting code determine the diversity weight from the residual kernel. When off, the α field is used directly.

Automatic alpha τ

Tolerance parameter for determining the automatic regression diversity penalty. Only used when automatic alpha is enabled.

Ensemble optimization objective

Optimize predictive performance, a diversity measure, or their combination. The diversity-only option can sacrifice accuracy for disagreement.

Performance slack [% of criterion range]

Allowed loss in performance, relative to the range of candidate scores, when searching for a more diverse ensemble. Zero does not permit a performance trade-off.

Ensemble size penalty

Same penalty as Size penalty above, shown in the diversity-only optimization branch. Zero disables regularization toward smaller ensembles.

Feature stability across CV1 partitions

Cross-CV1 probabilistic feature extraction is an advanced option for aggregating selected feature masks across inner cross-validation partitions.

Controls include a mode, a tolerance/selection cutoff, a minimum number of features and whether to prune/retrain individual models.

Enable cross-CV1 filter stability

Collect filter-selected feature masks over CV1 folds and permutations, calculate each feature’s selection frequency, and use that frequency to build revised masks. Requires consistent feature columns across folds.

How stability selects features

Agreement mode keeps features selected in at least the cutoff percentage of CV1 partitions and can lower the threshold if too few qualify. Top-N keeps a fixed number of the most frequently selected features. Top-% keeps a fixed percentage of ranked features; these are three different quantities.

Agreement cutoff / top-N / top-%

Agreement: percentage of CV1 selections a feature must appear in (e.g., 90 means 9 of 10). Top-N: number of highest-frequency features (e.g., 10). Top-%: share of highest-frequency features (e.g., 10% retains about 10 of 100 features).

Agreement tolerance window

Only for agreement mode. If fewer than the required minimum features pass the cutoff, the selection cutoff is lowered one percentage point at a time, down to the cutoff minus the tolerance. For example, 90% with window 25 can examine thresholds down to 65%.

Minimum feature count in agreement mode

Only for agreement mode. The selection cutoff is lowered until enough features pass; an error occurs if the tolerance window is exhausted. Not used by top-N or top-% selection.

Individual pruning or common mask

On: intersect the consensus-selected features with each original CV1 model’s own feature mask and retrain the model. Off: apply one common consensus mask to all CV1 models before retraining. Individual pruning can leave different masks across partitions.

Wrapper strategy

What does a wrapper do?

A wrapper compares candidate feature subsets by repeatedly evaluating a predictive model. It is generally more computationally demanding than a filter.

  1. Enable Use wrapper-based ensemble generation on Overview.
  2. Choose an algorithm, for example Greedy feature selection.
  3. Choose the data partitions used to evaluate candidate subsets.
  4. Adjust stopping and search settings only when appropriate.
Why might a control be missing? Wrapper optimization across multiple parameter settings appears only if the configured ML parameter grid makes this meaningful.

Choosing the wrapper search algorithm

Greedy feature selection adds or removes candidate features step by step. Its direction, feature-step size and stopping conditions determine the sequence of candidate subsets.

Other algorithms search more broadly:

  • Simulated annealing: stochastic exploration governed by a temperature schedule.
  • Genetic algorithm: a population of candidate subsets evolves through crossover and mutation.
  • Particle swarm optimization: a population-based search guided by candidate performance.
  • Path finder algorithm: a population-based optimization option.

Each method has its own settings.

How wrapper candidates are evaluated

CV1 data partitions for optimization controls which part of the inner validation design contributes to wrapper selection.

Parameter-optimization handling is shown only when the learner has more than one relevant parameter combination. If the grid contains a single combination, this choice is unnecessary and can remain hidden.

When wrapper optimization runs

Specifies whether wrapper search is performed in conjunction with hyperparameter optimization or after the best learner parameters are chosen. This can change computational cost and which learner settings are tested.

CV1 data partitions for optimization

Controls which CV1 cases determine the objective for comparing feature subsets. Training uses in-sample fit (optimistic); test uses held-out inner-fold predictions (usual default); full partition pools training and test before scoring; training + test evaluates training and test separately and averages the two criteria (with an optional training–test gap stop in greedy search).

Greedy search settings

  • Direction: add features (forward) or remove them (backward).
  • Feature sorting criterion: choose how candidate features are ordered.
  • Early stopping threshold: stop the search after the configured criterion is met.
  • Early stopping mode: interpret the threshold as a percentage or a feature count.
  • Feature stepping: change how many features are added or removed at a step.
  • Random block percentage: add randomized candidate blocks to the search.
  • Kneepoint detection: optionally identify a point of diminishing returns.

The Adaptive wrapper controls appear when ordinary early stopping is disabled by setting the threshold to zero. Additional adaptive settings are relevant only if that option is enabled.

Forward or backward

Forward starts with a small subset and adds features; backward starts with many and removes them. The direction changes the search trajectory and computation.

Early stopping threshold

Stop the feature search at a target remaining feature count or percentage (as specified below). Zero disables ordinary early stopping and permits the adaptive wrapper settings.

Count or percentage

Interpret the early-stopping threshold as a percentage of features or as an absolute feature count. The same numeric threshold has very different meaning under these modes.

Features per greedy step

Percentage of top-ranked candidate features added or removed as a block at each iteration. Zero disables block steps and leaves ordinary stepwise search.

Randomness within leading features

Draw a proportion of features at random from the leading ranked block rather than always taking the same best candidate. Zero disables randomness.

Detect performance knee

Optionally use the elbow of the feature-count versus performance curve to choose a stopping point.

Feature-sorting rule

Rank candidate features by their predictive performance or by model-derived feature weights (Guyon-style). Weight-based ranking is learner-dependent and may be unavailable for some models.

Training–test performance gap stop

For the separate training+test criterion, optionally stop when training performance exceeds CV1 test performance by too much.

Maximum allowed training–test gap

Percentage gap between training and CV1 test criteria that triggers early stopping when critical-gap stopping is enabled. Only relevant for the separate training+test optimization mode.

Greedy wrapper

Adaptive wrapper: selecting features using their similarity

The adaptive wrapper is an optional extension of Greedy feature selection. As the search adds or removes features, it uses the correlation between features to adjust which candidate to consider next. This can help avoid choosing nearly identical features repeatedly while allowing combinations of moderately related features.

The adaptive settings appear when Greedy feature selection is selected, Early stopping threshold is 0, and Enable adaptive wrapper is active. Ordinary early stopping hides these controls.

The adaptive settings affect the feature search, not the source data or the CV partitions.

Understanding the settings

Auto mode

Let the search adjust how strongly it uses its feature-similarity penalties as candidate performance changes. With Auto mode off, the Lambda value supplies a fixed strength. Auto mode does not automatically optimize every parameter shown below; the other displayed settings are retained unless you change them.

Lambda

How much the accumulated similarity-based adjustment influences candidate ranking when Auto mode is off. A higher value gives the adjustment more influence relative to prediction performance; a lower value keeps the search closer to ordinary greedy selection.

kNN neighbours

For each feature, the search identifies its most strongly correlated neighbours using absolute correlations in the training data. This value controls how many neighbours contribute to the adaptive updates. Higher values consider more relationships and can increase computation.

Gamma — memory

Controls how long previous similarity adjustments persist between selection steps. Values closer to 1 retain their influence for longer; smaller values let the search respond more quickly to recent selections.

rmax — adjustment limit

Caps the accumulated feature-specific adjustment so that repeated updates cannot increase it without bound.

eta0 — background adjustment

Adds a small general change to the feature-specific adjustment at each search step. It keeps the search history evolving even for features that are not close neighbours of the most recently selected feature.

eta1 — similarity update strength

Controls the size of the extra adjustment passed to features resembling a recently selected or removed feature. Increasing it makes similarity more influential in subsequent decisions.

φ center c

The similarity level around which the method favours moderately related features. Similarity is based on absolute correlation, from 0 (unrelated) to 1 (nearly identical). The default center is 0.55.

φ half-width w

Sets the width of the moderately similar region around the center. At the default center of 0.55 and half-width of 0.15, this region runs approximately from 0.40 to 0.70. The transition at its edges is smooth rather than abrupt.

β well

Sets the depth of the negative part of the similarity-response curve around the moderate-similarity region. A deeper well increases the relative preference for moderately related candidates.

β high

Controls the positive part of the response at very high similarity. Increasing it makes near-duplicate features contribute a stronger adjustment to future search decisions.

σ low

Controls how gradually the method enters and leaves the moderate-similarity region. Larger values make the transition smoother.

σ high

Controls how gradually the high-similarity adjustment turns on near the upper edge of the region. Smaller values make the rise sharper.

Reading the similarity curve

The preview below these settings shows how the response changes with feature similarity. The horizontal axis represents absolute correlation; the vertical axis shows the relative adjustment. A negative dip marks moderate similarity and a positive rise marks near-duplication. The curve helps you understand the shape of the settings; it is not a graph of your model's prediction performance.

Enable adaptive similarity-aware greedy search

Replace ordinary greedy choice with the similarity-aware penalty adjustment. Requires greedy search with the usual early-stopping threshold set to zero.

Wrapper ensemble construction

Choose what happens to wrapper-selected candidate subsets: no ensemble, optimization of multiple classifiers, agreement-based feature selection, or boosting.

Which wrapper subspaces qualify?

Select only the optimum, candidates within a performance range, candidates above a percentile, or all candidates. This is applied before ensemble construction.

Wrapper subspace cutoff

Controls the performance range or percentile for including wrapper-generated candidate subsets. Not used for winner-takes-all or all-subspaces.

Wrapper feature-subspace stepping

Fraction/percentage used to step through candidate feature-subset sizes during wrapper evaluation. Smaller steps permit a finer search but require more model evaluations.

Wrapper ensemble objective

Choose whether the wrapper ensemble emphasizes predictive performance, disagreement or both.

How much performance reduction is tolerated to seek more diverse wrapper-selected classifiers; expressed as percentage of the observed performance range.

Wrapper ensemble of subsets

Wrapper feature stability across CV1

This advanced option aggregates wrapper-selected feature masks across inner validation partitions. Its cutoff, tolerance, minimum feature count and prune/retrain options have the same purpose as the corresponding filter controls, but apply to wrapper outputs.

Enable cross-CV1 wrapper stability

Apply cross-fold selection-frequency analysis to wrapper-generated feature masks and retrain according to the resulting stable features.

How stability selects features

Agreement mode keeps features selected in at least the cutoff percentage of CV1 partitions and can lower the threshold if too few qualify. Top-N keeps a fixed number of the most frequently selected features. Top-% keeps a fixed percentage of ranked features; these are three different quantities.

Agreement cutoff / top-N / top-%

Agreement: percentage of CV1 selections a feature must appear in (e.g., 90 means 9 of 10). Top-N: number of highest-frequency features (e.g., 10). Top-%: share of highest-frequency features (e.g., 10% retains about 10 of 100 features).

Minimum feature count in agreement mode

Only for agreement mode. The selection cutoff is lowered until enough features pass; an error occurs if the tolerance window is exhausted. Not used by top-N or top-% selection.

Individual pruning or common mask

On: intersect the consensus-selected features with each original CV1 model’s own feature mask and retrain the model. Off: apply one common consensus mask to all CV1 models before retraining. Individual pruning can leave different masks across partitions.

CV2 / ensemble prediction

How are predictions combined?

CV2 is the outer cross-validation level used to estimate out-of-sample performance. This page controls how predictions from selected classifiers and CV2 partitions are handled. It does not construct the CV structure; that is configured elsewhere.

Retraining after feature/parameter selection

Retrain classifiers with the full CV1 partition controls whether selected models are refitted using the relevant full inner-training partition after selection.

Predicted labels or prediction scores?

For classification, CV2 ensemble metric can use predicted class labels (hard decisions) or continuous decision/probability values (soft decisions).

This specific selector is not shown for regression. Regression uses a different prediction representation, so a missing voting control is expected.

Combining repeated CV2 predictions

Mean ensemble prediction across CV2 permutations aggregates repeated predictions by averaging their ensemble outputs. Grand ensemble prediction combines the individual contributing predictions across repetitions. Grand ensemble prediction is the default.

Immediate retraining

This setting is available only in the specific combination where the ML optimization grid has at most one parameter combination and neither Filter nor Wrapper is enabled. It is therefore absent in many normal configurations.

Why are some settings hidden?

Only settings relevant to your current selections are displayed. An option may be hidden because:

  • Filter or Wrapper is not enabled.
  • The selected search method has different parameters.
  • The current analysis is regression rather than classification.
  • There is only one ML parameter combination.
  • Filter feature-subspace selection is not enabled.
  • A dependent option, such as boosting or adaptive search, is disabled.
