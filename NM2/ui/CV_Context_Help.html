Start here: what does cross-validation do?

CV2 (outer) holds cases completely outside model tuning and feature selection; its held-out predictions support the internal estimate of generalization. CV1 (inner) operates only within each CV2 training set to choose parameters, features and models. The nested structure keeps model selection separate from the outer evaluation.

Choose the split according to the population you want to predict: new people from similar settings (pooled), or people at entirely unseen sites/families/other groups (group-based). NeuroMiner learns preprocessing and feature-selection settings within the corresponding training partitions.

Pooled folds evaluate new cases drawn from the pooled sample; group-based designs evaluate transfer across defined groups. The number of cases or groups per fold influences the precision and stability of performance estimates.

Cross-validation framework

1 — Pooled: generate CV1 and CV2 folds from the pooled sample. Appropriate when observations can be exchanged between folds and your intended deployment population resembles the sampled population.

2 — Outer Leave-Group-Out / Inner pooled: hold out entire groups in CV2, but tune on pooled cases from the remaining groups. Useful for estimating transfer to an unseen acquisition site or cohort.

3 — Nested Leave-Group-Out: separate groups in both CV2 and CV1, so tuning also emphasizes cross-group transfer. 4 — Outer Leave-Group-Out / Inner Leave-Group-In: inner models are trained within individual groups and evaluated across groups; use for the specific scientific question of single-group model transfer.

A group identifier represents a scientific unit such as site or participant identity. Group-based CV holds out those units together; pooled CV distributes individual cases across partitions.

Outer CV2 partitioning

Repeated K-fold: divide the sample into K held-out portions per repetition. Every CV2 test portion remains unseen by model tuning. Leave-one-out: hold out one case at a time; this can be computationally expensive and yields small test partitions.

The framework controls whether these choices are available. Group-based frameworks select their CV2 test sets by the group-index variable instead.

Inner CV1 partitioning

CV1 divides each outer training partition into smaller training and validation sets. It is used to select hyperparameters, preprocessing choices and feature-selection settings; it is not the final independent evaluation.

Leave-one-out inside CV1 can greatly increase model fits, particularly with wrappers or grids. In grouped frameworks CV1 follows the grouping design instead of ordinary K-fold splitting.

Outer CV2 permutations

Number of independent resamplings of the outer folds. More repetitions expose the model to more train/test partitions and can stabilize aggregate estimates, but each repetition multiplies downstream computation. A permutation here is a repeat of fold assignment, not a label-shuffling significance test.

Leave-one-out and some group-based designs do not permit repeated partitions; their controls are hidden or fixed.

Outer CV2 folds

Number of held-out portions in each outer repetition. For example, 5 folds hold out roughly one fifth of the eligible cases per fold; 10 folds hold out roughly one tenth. Higher K uses more training cases per model but creates smaller test folds and more computation.

The fold count determines how many cases enter each test partition; high values make test folds smaller. Leave-one-out is a separate mode and does not require a negative fold count.

Inner CV1 permutations

Number of repeated subdivisions of each outer training set for parameter and feature selection. Repetition reduces dependence on a single random inner partition but increases the number of model fits. CV2 test cases remain outside this process.

Inner CV1 folds

Number of inner validation portions within each CV2 training partition. The smallest CV2 training partition limits the cases available for inner folds. Very small validation folds can yield variable performance estimates, especially for rare outcomes.

Outer CV2 group-index variable

Select a workspace vector assigning a group identifier to each case, in exactly the same case order as the active NM target. In leave-group-out CV2, all cases belonging to a held-out group are kept out of that outer training partition.

For example, a site/scanner identifier makes CV2 hold out one acquisition site at a time. The number of sites, their sizes and the outcome distribution across sites determine the resulting test partitions.

Inner CV1 group-index variable

The group index defines inner training/validation separation in nested group frameworks. For cross-site tuning, site identities define the groups; row numbers would instead describe individual records.

Group identifiers correspond to the current cases in the same order. In the single-group-training framework, inner training and test groups are distinct.

Multi-class decomposition

Only shown with more than two classes. One-vs-one: train a binary model for every class pair. One-vs-all: train one model per class against all remaining classes. These answer different binary subproblems and may respond differently to imbalanced class sizes.

Multi-group / no decomposition: leave the multiclass outcome intact for learners that handle multiple classes directly. This option applies to learning algorithms that accept the full multiclass outcome directly.

Leave-one-out CV fixes the decomposition setting to one-vs-all. Decomposition changes the binary learning problems, not just how results are displayed.

Equalize CV1 training partitions by undersampling

Enabling undersampling changes the distribution of cases used for model fitting. For classification, undersampling reduces the larger class relative to the smaller one; for regression it seeks a more even representation across the target histogram.

Equalization changes which cases are used for fitting inside CV1 and discards some training observations. It is not automatically better: it can waste data and change the effective training distribution. Equalization is applied to the CV1 training partition, not to the held-out CV2 test cases.

Equalization target (regression)

The balancing histogram can use the active numeric outcome or a selected covariate. Outcome-based equalization changes the sampling distribution of target values; covariate-based equalization changes the sampling distribution of that covariate.

Changing the balancing variable does not change what the model predicts. It changes the sampling plan used in CV1 training.

Regression equalization covariate

This field selects the numeric covariate whose distribution determines the balancing histogram. The histogram is calculated from its case-wise values, not the covariate name.

Minimum observations at lower histogram end

For regression equalization, this sets a minimum representation target near the lower end of the chosen distribution. Together with the upper-end and bin controls, it determines how the training sample is thinned across the histogram.

The original histogram shows how many observations occupy the distribution tails. Undersampling cannot create additional independent observations in sparsely populated ranges.

Minimum observations at upper histogram end

Companion minimum representation setting at the upper end of the regression target or selected covariate distribution. When few cases are available near this end, a high minimum may constrain the resulting balancing plan.

Histogram bins

Number of intervals used to describe the continuous target for regression undersampling. More bins represent finer distinctions but contain fewer cases each; fewer bins pool more heterogeneous values. The available sample size determines how many cases can occupy each bin.

Inspect original and equalized histograms

Original: examine the target distribution before equalization. Equalized CV1: inspect the actual training distribution after building a CV structure; this view requires generated folds. The difference between the histograms shows which parts of the range lost observations during undersampling.

Target bigger/smaller class ratio

For classification, set the intended ratio of larger to smaller class after training-fold undersampling. 1 aims for equal sizes; 1.5 allows 50% more majority-class than minority-class cases and is the default.

A more equal ratio may help minority-class learning but removes more majority-class examples. Sensitivity, specificity and calibration are assessed from outer CV2 test predictions on the original held-out cases.

Shuffle removed observations to CV1 test data

This option determines whether cases excluded from a balanced CV1 training partition are added to that CV1 validation partition. This changes the set used for hyperparameter/feature-selection assessment, not the outer CV2 holdout.

Keeping them can help assess candidate models against a less artificially balanced inner test set. Excluding them instead produces an inner test set without those removed cases.

Constrain pooled CV by a group-index variable

This option stratifies pooled folds by an additional grouping variable so that its categories are represented across folds. This is distinct from leave-group-out: constraining pooled CV distributes group levels across folds rather than keeping an entire group exclusively in the test set.

For example, stratifying by site represents the sampled mixture of sites across pooled folds; leave-group-out instead assesses performance on sites absent from training.

Constraint group-index vector

Select a numeric group-index vector with one entry per NM case, in the active case order. Its categories represent strata to distribute across pooled folds. Categories represented by few cases cannot contribute equally to every fold when the number of folds exceeds their case count.

Use part of the sample as exclusive test data

Reserve cases identified by a separate index for evaluation at the CV2 level, outside the ordinary eligible training sample. This is useful for a deliberately held-out subset that must not contribute to model fitting or inner selection.

An exclusive test subset comes from the current dataset; it is not an external cohort. Cases assigned to the exclusive group are reserved for CV2 evaluation by the selected group index.

Index variable for exclusive test cases

The index variable identifies which current cases belong to the exclusive test group. It is a case-aligned vector of group codes, not a free-text label.

CV level for exclusive test data

The exclusive group is reserved at the CV2 test level. This setting does not change the outcome labels or create a CV1-only holdout.

Build mode for an existing CV structure

Overwrite: replace current folds. Append to outer CV: add outer resampling entries. Append to inner CV: extend inner resampling. Rebuild without new permutations: regenerate compatible structure without increasing the permutation count.

These options appear during Build when a compatible CV structure already exists. The available append operations depend on the compatibility of the existing structure. Appending is not adding new subjects to the dataset.

Load/save CV structure and settings

The load path identifies a previously saved CVstruct_*.mat file; loading restores the stored CV partition structure and its generating settings. The save path designates where to write them. The adjacent selectors provide the file and directory paths.

A saved split is useful for comparing modeling pipelines on exactly the same train/test assignments. The saved fold indices refer to the cases and their order at creation; changing the population or its order changes the meaning of those indices.

Build, load and save

Build creates the actual CV1/CV2 training and test partitions from your chosen settings. Load restores previously stored folds and settings. Save stores the existing folds and settings in a MAT file; it does not generate new folds.

Before training, Build or Load a compatible CV structure. Editing fold numbers alone changes the proposed settings, not the already generated partition indices. Build and Load produce the CV structure consumed by training.
