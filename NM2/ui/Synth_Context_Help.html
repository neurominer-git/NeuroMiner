How synthetic training data are generated

NeuroMiner derives additional feature vectors from observed training data, using the selected generation method. Depending on the method, synthetic outcome labels and covariates are also constructed. These observations augment the training material; they do not represent new, independently observed subjects.

The choice of method determines which properties of the observed data are reproduced: local neighbourhood structure, minority-class density, a Gaussian approximation, a mixture of Gaussian distributions, or empirical marginal distributions with multivariate dependence.

Synthetic observations are generated from the data available to the corresponding training operation. The held-out evaluation cases are not used to fit the synthetic training population.

Generate synthetic data

Disabled: training proceeds without synthetic observations generated by this module. Enabled: the selected method produces additional training observations.

Enabling synthesis changes the composition of the training sample. Its effect depends on the generator, the number of generated observations or balancing fraction, and the characteristics of the observed training data.

Synthetic data generation method

kNN-based: selects an observed case, identifies nearby training observations, and averages their feature values. The synthetic label is the most frequent label among the selected neighbours.

ADASYN: adaptively generates minority-class observations by interpolation. It concentrates synthetic cases in neighbourhoods containing more observations from other classes, increasing representation of locally difficult regions.

PCAGauss: represents the joint feature, covariate and outcome data in principal-component space, draws Gaussian values for the component scores, and transforms the draws back to the original variables.

Gaussian mixture model (GMM): fits a mixture of Gaussian components to the joint data and samples from the fitted distribution. The component count is chosen from the specified candidate values using BIC or AIC.

Gaussian copula: estimates each variable’s empirical distribution and the dependence between variables using their ranks. Sampling combines those marginal distributions with the fitted dependence structure. For classification it generates within classes and retains the observed class proportions; for regression the continuous outcome is generated jointly with the predictors and covariates.

The methods impose different distributional assumptions. For example, a Gaussian approximation smooths the observed distribution, while the copula method uses empirical marginal distributions and a Gaussian dependence representation.

Standardization before distance analysis

This setting controls treatment of feature scales for distance-based synthetic generation. With Standardize data, the kNN generator standardizes predictors before calculating distances. With Data already standardized / not needed, it calculates distances using their existing scales.

When distances are computed across features with different units or variances, the most variable features can contribute more strongly. Standardization changes the neighbourhoods from which synthetic observations are constructed.

PCAGauss, GMM and Gaussian copula fit distributions rather than using the kNN distance calculation controlled here.

Synthetic data management

Use data permanently by writing it to disk: generated synthetic observations are retained for reuse during the configured analysis.

Recreate data in each model training run: synthetic observations are generated again for training runs instead of reusing a saved generated set. This allows different random realizations across runs.

Population uncertainty scale

Specifies how strongly the empirical calibration population is perturbed before synthetic cases are generated. At 0, the generator uses the observed training population without this additional resampling step; stochastic generation can still produce different samples.

For positive values, the generator resamples complete training rows using randomized sampling weights. Predictors, outcome labels and covariates stay paired. In classification, resampling preserves the number of calibration cases in each class. A value of 1 corresponds to Bayesian-bootstrap weights; higher values generate more uneven weights.

This setting changes uncertainty about the underlying training population, rather than the requested number of synthetic cases.

Nearest neighbours for interpolation

Sets the number of closest observed cases used by the kNN generator. Their predictor values are averaged to obtain a synthetic case; its label is determined by the most frequent label among those neighbours.

A smaller number emphasizes very local neighbourhoods. A larger number averages across more cases and can smooth local feature differences.

Distance measure

Defines which training cases count as nearest neighbours in the kNN generator.

  • Euclidean: straight-line distance across feature values.
  • Manhattan: sum of absolute feature differences.
  • Cosine: difference in feature-vector direction, based on the angle between vectors.
  • Mahalanobis: distance that accounts for covariance between features.

Different distance measures can identify different local neighbourhoods and therefore generate different synthetic values.

Number of synthetic observations

Specifies how many additional observations to generate with the kNN, PCAGauss, GMM or Gaussian copula method. The same value is shown when switching among these methods.

The generated cases augment the observed training cases; increasing the count changes the relative weight of model-generated data within training. ADASYN instead determines its generated count from class imbalance and the beta setting.

Beta value for degree of balancing

Controls the amount of minority-class oversampling performed by ADASYN. 0 leaves class counts unchanged, while 1 aims for approximately equal class sizes. Intermediate values achieve part of the required increase.

Beta is a fraction of the class-count difference to correct, not the final minority-class proportion. The number of generated cases also depends on the observed class imbalance.

k for density estimation

Sets the neighbourhood size ADASYN uses to estimate how many nearby cases belong to other classes. This local class mixture determines how strongly synthetic generation is allocated to each minority-class observation.

Changing this k changes the spatial scale at which local minority-class difficulty is measured.

k for SMOTE

Sets the number of minority-class neighbours used for ADASYN's SMOTE-style interpolation step. The synthetic feature values are drawn between an existing minority-class case and one of its minority-class neighbours.

This parameter controls local interpolation, whereas the density k controls the allocation of synthetic cases across minority-class regions.

Range of Gaussian components

Enter one or more positive integer candidate component counts, separated by spaces, commas or semicolons—for example, 1 2 3 4.

The GMM generator fits each candidate count and uses the selected information criterion to choose the mixture complexity. More components can represent more distinct subpopulations, but also require fitting more parameters and models.

Metric for selecting the number of components

The GMM chooses among the supplied component counts by minimizing either Bayesian Information Criterion (BIC) or Akaike Information Criterion (AIC).

Both balance fit against model complexity. BIC applies a sample-size-dependent penalty for additional parameters; AIC uses a fixed penalty. Consequently, the criteria can select different numbers of Gaussian components from the same training data.
