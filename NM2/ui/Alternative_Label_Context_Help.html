What is an alternative label?

A label is the outcome that a machine-learning model is trained to predict. When a dataset is initialized, it receives an initial outcome label. This configurator lets a new analysis predict a different outcome using the same imported cases and predictor data.

Example. A dataset originally set up to predict patient versus control status may also contain a continuous symptom score. Selecting that score as an alternative label lets you initialize an analysis that predicts symptom severity rather than diagnostic group.

Changing the label changes the prediction task; it does not replace the original outcome stored with the dataset. Analyses already completed for other outcomes retain their own targets.

Use alternative label

Off: newly initialized analyses use the dataset's original outcome. On: newly initialized analyses use the alternative label vector and learning framework configured below.

Disabling the option restores the original outcome as the active target. If the learning framework had changed, the original mode-dependent configuration is restored.

Label variable

Select a variable from the MATLAB base workspace that contains the new outcome. Load or create the variable before opening the configurator. The list shows variables that can represent a subject-level label vector.

The variable must contain one value per case, in the same case order as the dataset. The value at position 1 belongs to the first case, and so on. Selecting a different variable changes which outcome is predicted; it does not change predictor features.

For example, a workspace vector symptomScore with one numeric score for each case can be used as a regression outcome.

The selector lists the variable type, dimensions, number of distinct non-missing values, and a suggested task. Two observed values can represent either groups or a quantitative measurement; Learning framework determines how the values are treated.

When an alternative label is already stored, Keep stored label vector keeps those values without selecting another workspace variable.

New label name

Enter a descriptive name for the outcome, such as Symptom severity or Treatment response. The name identifies the target in analysis summaries and results; it is not the name of the MATLAB variable containing its values.

When external validation (OOCV) includes outcome labels, NeuroMiner uses these names to associate each external label with the analysis that predicts it. Different outcomes sharing a name cannot be distinguished by that mapping.

Learning framework

Classification predicts membership in a category, such as responder versus non-responder. The alternative-label classification pathway supports binary outcomes only; a vector with more than two distinct non-missing classes cannot be used in this mode.

Regression predicts a numerical outcome such as a symptom score. It uses regression-specific model settings and performance measures instead of classification settings and measures.

Selecting the variable supplies the values; selecting the learning framework determines how the model learns from those values. The initial suggestion is not binding.

With numeric binary class labels, codes 1 and 2 correspond to the two groups used in result plots. Coding the classes as 0 and 1 can affect group display even when model predictions are unchanged.

Group names, comma-separated

For classification, enter the two group names separated by a comma, such as Control, Patient. The names follow the class order in the label vector (for codes 1 and 2, the first name belongs to class 1).

These names appear in the classification results. They do not recode the outcome vector or change which cases belong to either class. This field is hidden for regression.

What changes when the learning framework changes?

Switching between classification and regression rebuilds task-dependent template settings, including fusion, stacking, preprocessing, learner parameters and feature-selection defaults. Those settings were defined for the original prediction task.

Selecting another outcome within the same learning framework does not trigger this reset. The new label is applied when the configurator closes successfully.

Compatibility with the cross-validation structure

The alternative label uses the existing cross-validation (CV) partitions. For a binary classification target, those partitions must contain the class observations required for class-specific learning and evaluation.

NeuroMiner checks the current CV structure when the alternative label is applied and rejects incompatible partitions. Rebuilding the CV structure for the new outcome derives its partitions from that outcome.
